# Диагностика и устранение неполадок

В этом документе собраны методы проверки работоспособности туннеля и решения типовых проблем.

---

## 1. Проверка состояния сервисов

### На Российском релее:
```bash
# Статус сервиса
sudo systemctl status whitelist-bypass-relay.service

# Просмотр логов в реальном времени
sudo journalctl -u whitelist-bypass-relay.service -f
```

### На Зарубежном выходе:
```bash
# Статус сервиса
sudo systemctl status whitelist-bypass-foreign.service

# Просмотр логов в реальном времени
sudo journalctl -u whitelist-bypass-foreign.service -f
```

## 2. Диагностика соединения между серверами

Если клиент подключен, но сайты не открываются, проверьте межсерверный туннель:

1. Подключитесь к **Российскому релею** по SSH.
2. Запустите встроенный скрипт прямого теста:
   ```bash
   bash scripts/run-direct-foreign-test.sh
   ```
3. Скрипт поднимет временный клиентский сокет на релее и запросит внешний IP через зарубежный сервер.
   * **Успешный результат**: `DIRECT_FOREIGN_EGRESS=<IP_ВАШЕГО_ЗАРУБЕЖНОГО_СЕРВЕРА>`.
   * **Ошибка**: Если вывод показывает ошибку хендшейка REALITY или таймаут, проверьте правильность `FOREIGN_REALITY_PUBLIC_KEY`, `FOREIGN_SHORT_ID`, `HOP_UUID` и доступность порта TCP/443 на зарубежном сервере.

## 3. Частые проблемы и их решение

### Проблема 1: «В обычном интернете VPN работает, но в режиме белых списков не подключается»
* **Причина**: IP-адрес вашего российского релея не входит в доверенный пул CIDR текущего мобильного оператора или региональной вышки.
* **Решение**:
  1. В облачной консоли (например, Yandex Cloud) пересоздайте/перепривяжите публичный IP-адрес инстанса (выделите новый статический IP из другого диапазона).
  2. Обновите IP в `config.json` на релее и в ссылке на клиенте.
  3. Проверьте маскировку SNI: некоторые операторы требуют точного соответствия SNI (`ya.ru`, `yandex.ru`, `gosuslugi.ru`).

---

### Проблема 2: «Ошибка REALITY handshake failed»
* **Причина**: Сайт, используемый для маскировки (например, `www.yahoo.com` или `ya.ru`), изменил настройки TLS (например, включил Post-Quantum Kyber или сменил IP), либо не совпадает `PublicKey` / `ShortId`.
* **Решение**:
  - Убедитесь, что `serverNames` и целевой `target` в `config.json` совпадают.
  - Проверьте доступность целевого домена с сервера командой:
    ```bash
    curl -vk https://ya.ru
    ```

---

### Проблема 3: «Не открываются сайты / DNS resolution failed»
* **Причина**: Мобильный оператор перехватывает стандартные незашифрованные DNS-запросы на порту 53.
* **Решение**:
  - В настройках вашего VPN-клиента включите опцию **Remote DNS (Удаленный DNS)**.
  - Настройте DNS-сервера внутри клиента: `1.1.1.1` (DoH) или `8.8.8.8` (DoH).

---

### Проблема 4: Конфликт с существующими веб-серверами (Nginx, Caddy, Apache)
* **Причина**: Порт TCP/443 уже занят другим веб-сервером.
* **Решение**:
  - Проверьте, кто слушает порт 443:
    ```bash
    sudo ss -tulpn | grep :443
    ```
  - Если на зарубежном сервере работает панель 3x-ui / Hysteria 2 на **UDP/443**, конфликта нет, так как Whitelist Bypass слушает **TCP/443**.
  - Если на сервере уже работает веб-сервер на TCP/443, настройте SNI-проксирование через HAProxy/Nginx stream или используйте отдельный чистый IP/VPS.
