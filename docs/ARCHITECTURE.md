# Архитектура и принцип работы Whitelist Bypass

В данном документе подробно рассматривается механика блокировок в режиме «белых списков» (allowlist) на мобильных сетях в РФ и архитектурные решения, заложенные в данный проект.

---

## 1. Механика режима «белых списков» (Allowlist)

Когда операторы сотовой связи переводят базовые станции или региональные сегменты в режим ограниченного доступа («белые списки»), фильтрация трафика происходит на нескольких уровнях сетевого стека:

```text
[Мобильное устройство] 
        │
        ▼
[Уровень 1: L3/L4 Фильтрация] ─── Проверяется IP назначения и порт (только TCP 443 / разрешенные IP)
        │
        ▼
[Уровень 2: L7 DPI / ТСПУ]    ─── Проверяется TLS ClientHello (SNI, ALPN, TLS Fingerprint)
        │
        ▼
[Российский сервис / Яндекс]
```

### Почему перестают работать обычные методы обхода?
1. **WireGuard / OpenVPN / Shadowsocks**: Блокируются по специфическим сигнатурам протоколов и по IP зарубежных дата-центров.
2. **UDP / QUIC / Hysteria 2 / TUIC**: Порт UDP/443 и любые нестандартные UDP-порты полностью отсекаются на уровне L4.
3. **Прямой VLESS Reality на зарубежный VPS**: Зарубежные IP-адреса отсутствуют в базе разрешенных CIDR оператора, поэтому пакеты сбрасываются еще на первом маршрутизаторе оператора.
4. **Внешний DNS (UDP 53 / DoH / DoT на зарубежные сервера)**: Запросы к внешним DNS блокируются или подменяются (DNS spoofing).

## 2. Принцип работы Whitelist Bypass

Для успешного прохождения проверки трафик должен одновременно удовлетворять двум обязательным критериям:
1. **L3-критерий**: Пакеты отправляются на IP-адрес из диапазона разрешенных российских провайдеров (например, Яндекс Облако, VK Cloud, Selectel).
2. **L7-критерий**: В первом TLS-пакете (`ClientHello`) доменное имя SNI указывает на разрешенный сервис (например, `ya.ru`), а структура TLS-хендшейка в точности имитирует современный браузер Chrome (`uTLS / fp=chrome`).

### Схема двухзвенной передачи

```text
+-----------------------------------------------------------------------------------+
| 1. Мобильный клиент                                                               |
|    - Протокол: VLESS over TCP                                                     |
|    - Маскировка: REALITY (SNI: ya.ru, FP: chrome, Flow: xtls-rprx-vision)         |
|    - Назначение: IP Российского Релея (порт 443)                                  |
+----------------------------------------+------------------------------------------+
                                         |
                                         | TCP/443 (DPI видит легитимный HTTPS ya.ru)
                                         v
+-----------------------------------------------------------------------------------+
| 2. Российский Релей (Yandex Cloud / VK Cloud)                                     |
|    - Входящий поток (Inbound): Принимает VLESS Reality на порту 443                |
|    - Маршрутизация (Routing): Перенаправляет весь входящий поток в Outbound       |
|    - Исходящий поток (Outbound): VLESS Reality -> Зарубежный VPS                  |
+----------------------------------------+------------------------------------------+
                                         |
                                         | TCP/443 (Межсерверный VLESS Reality туннель)
                                         v
+-----------------------------------------------------------------------------------+
| 3. Зарубежный Выход (Foreign Exit VPS)                                            |
|    - Входящий поток (Inbound): Принимает межсерверный VLESS Reality              |
|    - Исходящий поток (Outbound): Freedom (прямой доступ в Интернет)               |
+----------------------------------------+------------------------------------------+
                                         |
                                         | Чистый интернет без цензуры
                                         v
+-----------------------------------------------------------------------------------+
| 4. Конечные ресурсы (Telegram, YouTube, Google, любые сайты)                     |
+-----------------------------------------------------------------------------------+
```

## 3. Особенности компонентов

### XTLS-Vision Flow (`xtls-rprx-vision`)
- Анализирует TLS-трафик внутри туннеля. При прохождении TLS-рукопожатия внутреннего соединения переключается в режим прямой передачи байт («vision»), устраняя двойное шифрование и дополнительный оверхед.
- Защищает от детектирования протокола по анализу энтропии и длины пакетов (padding).

### REALITY Masking
- В отличие от традиционного TLS, серверу не требуется собственный домен и валидный сертификат Let's Encrypt.
- REALITY использует открытый ключ реального сайта (например, `ya.ru` или `www.yahoo.com`) для проверки подлинности клиента. Сторонний сканер или цензор при попытке прощупать порт получает настоящий TLS-сертификат и ответ целевого сайта.

### Обработка DNS
- Клиентские DNS-запросы упаковываются внутрь VLESS-туннеля и резолвятся уже на зарубежном сервере (через Cloudflare 1.1.1.1 или Google 8.8.8.8). Это предотвращает утечки DNS и защищает от DNS-блокировок.

## 4. Требования к выбору серверов и IP-адресов

1. **Российский релей**:
   - Наиболее стабильные результаты показывают IP-адреса крупных российских облачных провайдеров: **Yandex Cloud**, **VK Cloud**, **Selectel**.
   - Должен быть выделен статический публичный IPv4.

2. **Зарубежный сервер**:
   - Любой VPS за пределами РФ (Нидерланды, Германия, Швеция, Финляндия и др.) со скоростью канала от 100 Мбит/с.
   - Порт TCP/443 должен быть свободен для сервиса Whitelist Bypass.
